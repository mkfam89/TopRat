When to use AI instead of a template

When your skills already cover a posting, the run copies the matching template — free, instant, no tokens. AI tailoring is for the postings your skills don't already cover. This is where that line sits.

How many AI resumes per scheduled run

Each scheduled run sorts by local jobs first, then best skill match and AI-tailors the top N. Only AI resumes count against the cap — a template copy is free and instant, so those are never capped, and neither is a job you queue yourself with the Tailor button.

Off-machine backup Copies your job history to a private repo, so a dead laptop doesn't take it. optional

Every daily run already commits a local checkpoint — an undo for a corrupted tracker or a bad resume — and that happens whether or not these fields are filled in. A remote URL only adds the second copy that lives somewhere else. Name and email are just the commit author; Git refuses to commit without them and they log you in to nothing.

Use a private repository. These commits contain your job search: employers, notes, salary figures, and your resume content.
HTTPS or SSH, any host. Stored in config/git.json, which Git ignores — your identity and URL never enter the repository.
Data folder location Move your profile, tracker, and resumes somewhere backed up. Needs a restart. optional

Holds all personal data — config/, the tracker and CSVs, the tailored resumes, and your resume_template/ base resumes. By default it is a user_data_<your initials> folder inside the app folder, so the whole install is one self-contained thing to copy, back up, or hand to another machine. Move it out if you would rather keep your data somewhere separately backed up; the app's code stays where it is either way.

Full path. The app creates the folder but moves no files — copy your existing data there before you restart.
